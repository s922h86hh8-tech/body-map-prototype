# 単体レビュー v0.3：表示解像度と陰影

2026-10-23。ユーザーの「もう少しピクセル解像度上がらない？」に対応。
公開予定: https://s922h86hh8-tech.github.io/body-map-prototype/experiments/cleanroom-bone-review-v0.3.html

## 変更したこと
- 高精細/軽量の表示画質切替。高精細はCSS1px当たり max(2,min(3,devicePixelRatio)) を要求し、各Canvasは240万画素以内に制限。軽量は1倍（同上限あり）。従来はDPR上限2で、通常1倍画面では1倍だった。
- 旧版の三角形ごとの一色塗りと輪郭ストロークを、頂点法線から計算した照明値の画素補間へ変更。法線と簡易遮蔽係数は面積で重みづけして共有頂点へ集計。
- Canvas2DのImageDataへ独自に描画。三角形間の前後関係は画素ごとの深度バッファで処理する。WebGLや外部ライブラリ/メッシュは不要。
- 拡大範囲・カメラは画質切替で保持。原著資料/形状の比較操作は維持。

## 変わらないことと限界
骨の頂点・三角形・距離場/断面・造形値は単体v0.2と同じ。頭蓋一式33,425頂点/66,738三角形、腰椎19,817頂点/39,634三角形。画面の滑らかさを上げたもので、解剖学的精度を向上・承認したという意味ではない。眼窩縁等の幾何学的な段差や粗い輪郭は残る。歯冠も簡略形状のまま。頭蓋内部や実骨の微細構造/骨密度を再現するものではない。
全身採用は保留。既存ページ・アプリ・GLB・大腿骨詳細を維持。iPhone実機、独立した骨面監査、自己交差厳密検査は未完了。

## 再現と検証
python tools/cleanroom/build-bone-review-v0.3.py
node tools/cleanroom/check-bone-review-v0.3.cjs

Python/Node/@napi-rs/canvasを使用。v0.2のHTMLハッシュを固定し、骨形状コード/準備コードが完全一致することをテスト。骨面の独立監査はしない。
- 新頭蓋/新腰椎の頂点数・面数一致。
- DPR3、CSS400×360を高精細1200×1080・軽量400×360として実描画し寸法を確認。
- 画素の描画、頂点照明/法線の有限値、画質切替後の描画結果の再現一致、拡大状態維持、リセット、前版形状の表示、顎/歯冠表示を検査。
- 前後2枚のテスト三角形の提出順を入れ替えても結果画像が一致することを確認。全形状の自己交差検査ではない。
- 同じ新形状/カメラのまま従来描画と新描画を比較し目視。docs/validation/cleanroom-bone-review-v0.3-comparison.jpg。
- 新描画1回のローカル参考値: 頭蓋336ms、腰椎203ms（1200×1080、初回形状生成を含めない）。端末の実測速度ではない。重い場合は軽量へ切替。
- 結果: docs/validation/cleanroom-bone-review-v0.3.json。公開・ブラウザ確認は別記録へ保存する。

次はiPhoneでの高精細/軽量切替と拡大操作の確認、必要に応じた描画負荷調整。骨面の改善は表示解像度とは別に、v0.2引継ぎの監査項目を継続する。
