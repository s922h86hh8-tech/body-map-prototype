# 単体レビューv0.4：拡大時の輪郭

2026-10-23。ユーザーの「大きくなった時にも綺麗には見たいな」に対応。
公開予定: https://s922h86hh8-tech.github.io/body-map-prototype/experiments/cleanroom-bone-review-v0.4.html

## 意図と変更
v0.3はピクセル数と陰影を改善したが、粗い三角形の輪郭や眼窩縁の凹凸が残った。今回、新形状の表面抽出の間隔を細かくし、同じ独自の陰関数を高い密度で標本化する。

|対象|v0.3以前の間隔|v0.4の間隔|
|---|---:|---:|
|頭蓋・顔面|0.5|0.3|
|下顎|0.4|0.25|
|腰椎|0.25|0.18|

いずれも無単位の描画座標。人体の測定間隔/mmではない。
- 独自の骨の設計式、断面、寸法/角度の制作値はv0.2と共通。新しい解剖学資料やスキャン由来の形状を追加したものではない。
- 頂点/三角形数と離散化された表面は変わる。形状の式が同じでも同一メッシュという意味ではない。
- v0.3の滑らかな陰影・画素深度判定、高精細/軽量切替を継続。拡大上限を4倍から6倍へ変更。
- 新ページの旧比較は、直前v0.3と同じ骨面（v0.2の設計式/粗い間隔）。表示は共通の新描画方式。以前の単体v0.1を旧比較にはしない。
- 比較3図は旧/新で共通の中心・縮尺。視野や見かけを合わせて比較できる。

## 制作・再現
python tools/cleanroom/build-bone-review-v0.4.py
node tools/cleanroom/check-bone-review-v0.4.cjs

Python/Node/@napi-rs/canvasを使用。v0.3HTMLのハッシュを固定し、v0.2の骨形状定義から間隔だけ変えてv0.4を構築する。v0.3の前比較をv0.2の骨面へ置換。
ページは単体HTML、外部メッシュ/スクリプト不要。初回は端末側で形状を生成するため時間がかかる。描画の「軽量」は画素数の切替であり、形状生成の細かさを戻すものではない。iPhone実機の待ち時間や拡大/回転追従は未確認。

## 検証範囲
- 両対象×旧/新の有限座標、面積、三角形インデックス、新メッシュの連結数、辺数/辺方向、符号付き体積を検査。
- 固定3図、部分拡大5箇所、同対象の旧/新切替時の拡大維持、リセット、方向、下顎/歯冠の表示、回転/ピンチ、直近選択優先をVMで確認。
- 実HTMLのCanvas2Dを@napi-rs/canvasで描画し、旧/新の3図と拡大5箇所を目視。
- 初期検査で、腰椎の格子点付近に非常に小さい三角形と未参照頂点を検出。交点が格子端点のごく近くにある場合の統合判定を補間係数1e-7から1e-4へ変更し、面に使われない頂点を整理した。骨の設計式は変えず、旧/新共通の表面抽出処理へ適用。境界や不正辺を検査対象から除外していない。
- 4倍の眼窩拡大で旧/新を同じ視点・ピクセル数で比較し、6倍上限とリセットも検査対象に追加。
- 技術検査は人体の骨面との定量的一致・解剖学的承認・自己交差の厳密検査ではない。
- 結果と画像: docs/validation/cleanroom-bone-review-v0.4.json、同名-skull.jpg/-lumbar.jpg（上段は前版相当、下段は細密）、-details.jpg。

## 残ること
頭蓋の内部・縫合・骨厚、顎関節や咬合、個々の歯、腰椎レベル/実寸/骨面精度の監査は未完了。微細な骨の凹凸や骨密度を表現するものではない。陰関数の表面自体にある角や凹凸は、分割数だけでは消えない。必要な骨面の改善は別途資料照合して実施する。
全身への採用は保留。既存アプリ・全身版・大腿骨詳細・GLBは維持する。次はiPhone実機の表示/待ち時間、ユーザーの拡大比較、独立した骨面監査と必要な造形修正。
